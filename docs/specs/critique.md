# critique (formerly dz-review)

Rust port of `dz-review` (`packages/tools/dz-review`), renamed `critique`. Crates: `critique-core` (pure: scanner, ids, reference map, timestamps, agent types, no I/O, builds for wasm32), `critique-cli` (binary `critique`, adapters for file system, git, clock, terminal), `critique-wasm` (JSON facade for the VS Code extension; the only place where positions become UTF-16). Its single entry point `reviewItems(file, text, mapJson | null)` returns `{ items, map }`: every item with its persistent id (assigned over all items before any filtering, like `list`, `session start` and `agent`), display id (shortest unique prefix over every id of the project: the reference map after assignment, all files, plus the file's own ids), kind, state, UTF-16 range, lines, metadata timestamp and conversation messages; `map` is the `reference-map.json` content to write, `null` when unchanged. File I/O stays in the extension.

Behaviour is pinned by `tests/blackbox/cases/dz-review` (553 `parity` cases recorded from the Deno tool; the 568 once written here was stale before this change) plus 41 `new-spec` cases (the table below). Run: `tests/blackbox/run.sh --ref rust --tool dz-review`.

## Rename and state directory

| Item                                 | Before (`dz-review`)                           | Now (`critique`)                                                             |
| ------------------------------------ | ---------------------------------------------- | ---------------------------------------------------------------------------- |
| Binary, messages                     | `dz-review`                                    | `critique`                                                                   |
| State directory                      | `.dz-review` (Git root, else cwd)              | `.critique` (same placement)                                                 |
| Ignore file                          | `.dz-review-ignore`                            | `.critique-ignore`                                                           |
| Env variables                        | `DZ_REVIEW_STATE_DIR`, `DZ_REVIEW_IGNORE_FILE` | `CRITIQUE_STATE_DIR`, `CRITIQUE_IGNORE_FILE` first, the old names still read |
| `--state-dir`, `--ignore-file`, `-C` | unchanged                                      | unchanged (`--state-dir` beats env beats default)                            |

**Read fallback.** When the state directory is the default one, `.critique` does not exist and `.dz-review` does, `.dz-review` is _read_ (session snapshot, `reference-map.json`). Everything is _written_ under `.critique` (the first write copies the legacy map entries); the legacy directory is never modified. The same rule applies to the ignore file. A configured directory (`--state-dir`, env) has no fallback. `.critique/` and `.dz-review/` are both always ignored when discovering files.

**Legacy identity switch.** `CRITIQUE_COMPAT_DZ_REVIEW=1` (any value but empty or `0`) makes the binary behave as `dz-review`: name in messages and `agent-instructions`, `.dz-review` / `.dz-review-ignore` defaults, no fallback. It exists so that the legacy suite (cases written against `dz-review`) runs unchanged; `tests/blackbox/refs/rust/dz-review` sets it unless a case sets the variable to an empty string, which is how the `new-spec` cases `global/new-*` test the real defaults.

## Ids

Unchanged and byte-identical to the TS values (they are persisted in user documents): `rvw_` + base62 (`0-9A-Za-z`) of FNV-1a 64 over the UTF-16 code units of `file\0kind\0anchor` (anchor truncated to 160 UTF-16 units, so a truncation inside a surrogate pair still hashes like the TS). Timestamps use the other base62 alphabet (`0-9a-zA-Z`). `critique-wasm` and the CLI call the same functions; a test pins the historical vectors.

## Quirks kept on purpose

- Items collected as annotations have no `roles`: `--open`, `--wip`... without `--conversations` never match a conversation (every annotation-collected item counts as `handled`); with `--conversations` the real status is used.
- Selection flags (`--pending`, `--open`, ..., `--*-conversations`) are resolved in a fixed order, not left to right (the TS rebuilt argv from an options record); likewise `--context` then `--context-before/after`.
- `{?? a ?}` (closed by `?}`) is a conversation for the conversation collector but not an annotation.

## Not ported / backlog

- `Date` strings other than ISO forms in `now --date` (V8 legacy parser).
- Interactive `review` on a terminal (line editing); only the stdin-driven mode is implemented and tested.
- Ignore-file discovery sorts names bytewise (TS used `localeCompare`).
- CLI display ids are shortened over the items of each command (listing, snapshot, target files), the extension's over the whole project (reference map and file ids): the panel may show a longer id than the CLI; both resolve (see `agent/show-longer-id`).
