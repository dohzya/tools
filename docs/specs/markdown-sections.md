# Markdown sections: parsing rules and migration decisions

Status: accepted 2026-10-29 (decisions recorded during the Deno → Rust migration, see [`docs/plans/2026-10-28-runtime-migration.md`](../plans/2026-10-28-runtime-migration.md)).

Scope: how `md` (and anything built on its sections: `dz-review`, MRFI scope references) decides what a heading is, where a section starts and ends, and how edits behave. The previous TypeScript parser (line regex + naive fence toggle) is **not** the reference: where it differs from CommonMark 0.31.2, CommonMark wins (evidence: [`reports/MD-PARSING.md`](../explorations/runtime-migration/reports/MD-PARSING.md), [`reports/SPIKE-B-RUST.md`](../explorations/runtime-migration/reports/SPIKE-B-RUST.md)).

## Principles

1. A CommonMark parser locates headings and block ranges; edits are text splices on the source. Markdown is never re-rendered, so untouched bytes stay identical.
2. Frontmatter is outside Markdown and handled by our own rule (below).
3. **Section ids do not change** for existing headings: `sha256("level:title.toLowerCase().trim():occurrence")`, first 8 hex chars, with the raw heading text (closing `#` included). Class name `Blake3HashService` in the TS code is historical; the algorithm is SHA-256.
4. Known consequence: when headings appear or disappear because of the rules below, the occurrence index of later headings with the same level and title can shift, hence their ids.

## Section extents (unchanged)

A section runs from its heading to the next heading of level <= its own (`--deep`) or to the next heading of any level (default), or to the end of the file. Only document-level headings count (not those inside block quotes or list items).

## Verification

- Corpus: `docs/explorations/runtime-migration/md-corpus/` (80 files) stays as a non-regression suite, with the expected outline for each file.
- Properties (spike B): bytes outside the touched range are unchanged; writing the current body is a no-op; append then remove restores the file; the CRLF outline equals the LF outline; no heading is found inside code or HTML blocks; reparsing after an edit yields the expected outline.
- Editor/CLI agreement: the VS Code extension (wasm) and the `dz-review` CLI use the same core crate; parity is tested on the corpus.
- MRFI: references written by the TS implementation must still resolve; `mrfi` needs test vectors generated from the TS implementation (fuzzy hashes, compact envelope).

## Backlog (not part of the migration)

- Setext to ATX conversion: a command or option rewriting setext headings (`Title` + `===`/`---`) as ATX (`#`/`##`). Level and title are unchanged, so section ids stay the same; multi-line setext titles are joined with a space (as for the ids). To be designed after parity is reached.
