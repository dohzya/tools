# Runtime migration exploration (Deno → Bun / Rust / Mojo)

Context: Deno is being abandoned after the Cloudflare acquisition. This folder keeps the artifacts of a short experiment (October 2026) comparing Bun, Rust and Mojo on a small slice of the toolset: `md read`, `wl list`, `wl show`.

The worktask trace lives in `.worklog` (task `c2gku6`, local only); this README is the durable summary.

## Layout

| Path                                                    | Content                                                                          |
| ------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `SPEC.md`                                               | Black-box spec of the slice (contract, formats, out-of-scope list)               |
| `fixtures/`, `expected/`, `cases.json`, `cases.src.tsv` | Inputs and reference outputs (39 cases), generated by the TS/Deno CLI            |
| `run_cases.sh`                                          | Oracle: `./run_cases.sh "<impl command>"` → `TOTAL: n/39 passed`                 |
| `tools/`                                                | Wrappers around the TS reference (absolute paths: adapt to your checkout)        |
| `md-corpus/`                                            | 80 Markdown files (64 hand-made edge cases, 16 real docs) for parser comparison  |
| `reports/`                                              | Findings per topic (crates, YAML editing, Markdown parsing, standalone binaries) |
| `spike-b/`                                              | Spec of the CommonMark-based section editing spike                               |

`fixtures/`, `expected/` and `md-corpus/` must stay byte-exact: they are excluded from `deno fmt`.

## Results in short

- All three implementations (Bun, Rust, Mojo) pass the 39 cases. Startup of `md read`: Deno 287 ms, Bun ~30 ms (16 ms compiled), Mojo ~8 ms, Rust ~1–3 ms.
- Mojo is dropped: everything beyond the stdlib is hand-written, no cross-compilation, runtime `.so` files must ship next to the binary, licence of those files unclear.
- Standalone binaries: Deno compile 95 MB, Bun compile 95 MB (8 targets cross-compiled from Linux), Rust 730 KB.
- The current TS rewrites the whole YAML frontmatter through `@std/yaml` (comments, quoting, anchors lost) and silently overwrites it when parsing fails. Rust `yaml-edit` or a textual fallback does better.
- The TS section parser is not CommonMark-correct (fences, HTML blocks, CRLF, indented ATX, setext). Six CommonMark parsers agree with each other against it. See `reports/MD-PARSING.md`.
- The section id is SHA-256 (8 hex chars) despite the historical `Blake3HashService` name.

## Open question

Bun vs Rust is undecided. Bun keeps the existing code and costs the least; Rust gives a tiny standalone binary and the best frontmatter editing story.
